# CodeCraftHub Course API

CodeCraftHub is a Spring Boot REST API for managing courses. Course data is stored in a local `courses.json` file instead of a database.

The API supports creating, reading, updating, and deleting courses.

## Features

- Create courses
- Retrieve all courses
- Retrieve a course by ID
- Update existing courses
- Delete courses
- JSON file-based data storage
- Automatic creation of `courses.json`
- Auto-generated course IDs starting from `1`
- Auto-generated creation timestamps
- Request validation
- Required field validation
- Course status validation
- Date format validation
- Helpful JSON error responses
- Jackson JSON processing
- Atomic file writes using a temporary file

## Technologies

- Java 17+
- Spring Boot 3
- Spring Web
- Spring Validation
- Jackson
- Maven
- JSON file storage

## Course JSON Format

Each course contains the following fields:

| Field | Required | Description |
|---|---:|---|
| `id` | No | Automatically generated numeric ID |
| `name` | Yes | Course name |
| `description` | Yes | Course description |
| `target_date` | Yes | Target date in `YYYY-MM-DD` format |
| `status` | Yes | Must be `Not Started`, `In Progress`, or `Completed` |
| `created_at` | No | Automatically generated timestamp |

Valid status values are case-sensitive:

```text
Not Started
In Progress
Completed
```

## API Documentation

### Create a Course

Creates a new course.

```http
POST /api/courses
```

#### Request

```bash
curl -X POST http://localhost:8080/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Java Spring Boot",
    "description": "Learn how to build REST APIs with Spring Boot.",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }'
```

#### Response

Status:

```text
201 Created
```

Example response:

```json
{
  "id": 1,
  "name": "Java Spring Boot",
  "description": "Learn how to build REST APIs with Spring Boot.",
  "target_date": "2026-12-31",
  "status": "Not Started",
  "created_at": "2026-10-14T12:30:45.123Z"
}
```

The `id` and `created_at` fields are generated by the application and should not be supplied when creating a course.

---

### Get All Courses

Returns all courses stored in `courses.json`.

```http
GET /api/courses
```

#### Request

```bash
curl http://localhost:8080/api/courses
```

#### Response

Status:

```text
200 OK
```

Example response:

```json
[
  {
    "id": 1,
    "name": "Java Spring Boot",
    "description": "Learn how to build REST APIs with Spring Boot.",
    "target_date": "2026-12-31",
    "status": "Not Started",
    "created_at": "2026-10-14T12:30:45.123Z"
  },
  {
    "id": 2,
    "name": "REST API Design",
    "description": "Learn REST API design principles.",
    "target_date": "2027-01-15",
    "status": "In Progress",
    "created_at": "2026-10-14T12:35:20.456Z"
  }
]
```

If no courses exist, the API returns:

```json
[]
```

### Get a Course by ID

Returns a specific course.

```http
GET /api/courses/{id}
```

#### Request

```bash
curl http://localhost:8080/api/courses/1
```

#### Response

Status:

```text
200 OK
```

Example response:

```json
{
  "id": 1,
  "name": "Java Spring Boot",
  "description": "Learn how to build REST APIs with Spring Boot.",
  "target_date": "2026-12-31",
  "status": "Not Started",
  "created_at": "2026-10-14T12:30:45.123Z"
}
```

If the course does not exist, the API returns `404 Not Found`.

---

### Update a Course

Updates an existing course.

```http
PUT /api/courses/{id}
```

The course ID and `created_at` timestamp cannot be changed. The request body must include all required fields.

#### Request

```bash
curl -X PUT http://localhost:8080/api/courses/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Advanced Java Spring Boot",
    "description": "Build production-ready REST APIs with Spring Boot.",
    "target_date": "2027-01-31",
    "status": "In Progress"
  }'
```

#### Response

Status:

```text
200 OK
```

Example response:

```json
{
  "id": 1,
  "name": "Advanced Java Spring Boot",
  "description": "Build production-ready REST APIs with Spring Boot.",
  "target_date": "2027-01-31",
  "status": "In Progress",
  "created_at": "2026-10-14T12:30:45.123Z"
}
```

---

### Delete a Course

Deletes a course by ID.

```http
DELETE /api/courses/{id}
```

#### Request

```bash
curl -X DELETE http://localhost:8080/api/courses/1
```

#### Response

Status:

```text
204 No Content
```

A successful delete does not return a response body.

If the course does not exist, the API returns `404 Not Found`.

## Validation

The following fields are required:

- `name`
- `description`
- `target_date`
- `status`

The `target_date` field must use this format:

```text
YYYY-MM-DD
```

Example:

```text
2026-12-31
```

The `status` field must exactly match one of these values:

```text
Not Started
In Progress
Completed
```

### Invalid Request Example

```bash
curl -X POST http://localhost:8080/api/courses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "",
    "description": "",
    "target_date": "31-12-2026",
    "status": "Pending"
  }'
```

Example response:

```json
{
  "timestamp": "2026-10-14T12:40:00Z",
  "status": 400,
  "message": "Validation failed",
  "fieldErrors": {
    "name": "name is required",
    "description": "description is required",
    "targetDate": "target_date is required",
    "status": "status must be exactly one of: Not Started, In Progress, Completed"
  }
}
```

Depending on the invalid date value, an incorrectly formatted date may instead return:

```json
{
  "timestamp": "2026-10-14T12:40:00Z",
  "status": 400,
  "message": "Invalid JSON or date format. target_date must use YYYY-MM-DD.",
  "fieldErrors": null
}
```

## Error Responses

### Course Not Found

Status:

```text
404 Not Found
```

Example:

```json
{
  "timestamp": "2026-10-14T12:45:00Z",
  "status": 404,
  "message": "Course with id 99 was not found",
  "fieldErrors": null
}
```

### Invalid JSON

Status:

```text
400 Bad Request
```

Example:

```json
{
  "timestamp": "2026-10-14T12:46:00Z",
  "status": 400,
  "message": "Invalid JSON or date format. target_date must use YYYY-MM-DD.",
  "fieldErrors": null
}
```

### File Storage Error

Status:

```text
500 Internal Server Error
```

This can occur when the application cannot create, read, or write `courses.json`.

## Troubleshooting

### 1. `java: command not found`

Java is not installed or is not available in your system `PATH`.

Install Java 17 or later and verify it:

```bash
java -version
```

If Java is installed but the command still fails, configure the `JAVA_HOME` environment variable.

---

### 2. `mvn: command not found`

Maven is not installed or is not available in your system `PATH`.

Install Maven and verify it:

```bash
mvn -version
```

Alternatively, if the project includes the Maven Wrapper, use:

```bash
./mvnw spring-boot:run
```

On Windows:

```powershell
mvnw.cmd spring-boot:run
```

---

### 3. Port 8080 is already in use

Another application may already be running on port `8080`.

Stop the application using the port, or start CodeCraftHub on another port:

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8081"
```

The API will then be available at:

```text
http://localhost:8081/api/courses
```

---

### 4. `courses.json` is not created

The file is created in the application's current working directory.

Check the directory from which the application was started. For example, if you run:

```bash
mvn spring-boot:run
```

from the project root, `courses.json` should be created in the project root.

Make sure the application has permission to create files in that directory.

---

### 5. File read or write errors

Check the following:

- The directory is writable.
- `courses.json` is not locked by another application.
- The file is valid JSON.
- The application user has permission to read and write the file.
- The disk is not full.

A valid empty data file should contain:

```json
[]
```

If the file has become corrupted, back it up and replace its contents with:

```json
[]
```

Note that replacing the file contents will remove the stored courses.

---

### 6. Invalid date format

Use the exact date format:

```text
YYYY-MM-DD
```

Correct:

```json
{
  "target_date": "2026-12-31"
}
```

Incorrect:

```json
{
  "target_date": "12/31/2026"
}
```

Incorrect:

```json
{
  "target_date": "31-12-2026"
}
```

---

### 7. Invalid status value

Status values are case-sensitive and must be one of:

```text
Not Started
In Progress
Completed
```

For example, this is invalid:

```json
{
  "status": "completed"
}
```

Use:

```json
{
  "status": "Completed"
}
```

---

### 8. Course ID not found

Course IDs are generated automatically and start at `1`.

Retrieve all courses first:

```bash
curl http://localhost:8080/api/courses
```

Then use an existing ID with the `GET`, `PUT`, or `DELETE` endpoint.

Deleted IDs are not reused.

---

### 9. Request body is rejected

Make sure to include the `Content-Type` header:

```bash
-H "Content-Type: application/json"
```

Also verify that the request body is valid JSON and includes all required fields.

## Testing with Postman

To test the API using Postman:

1. Start the application.
2. Create a new Postman request.
3. Set the request URL to:
   ```text
   http://localhost:8080/api/courses
   ```
4. Select the appropriate HTTP method.
5. For `POST` and `PUT` requests:
    - Open the **Body** tab.
    - Select **raw**.
    - Select **JSON**.
    - Enter a valid course object.
6. Send the request.

Example Postman request body:

```json
{
  "name": "Spring Boot Fundamentals",
  "description": "Learn the fundamentals of Spring Boot.",
  "target_date": "2026-12-31",
  "status": "Not Started"
}
```
